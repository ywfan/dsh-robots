# 设计与验收

## 机器人是预先准备好的能力

创建时确定角色、工作区、模型、知识、技能和流程。AI 可以协助整理草稿，负责人检查后发布。调用者只需提供本次任务，运行从一个固定版本开始。任务中的反馈可以积累为候选改进，确认后由后续任务使用。已运行的任务保留自己的版本。

## 代码按四块阅读

| 模块 | 文件 | 负责的约束 |
| --- | --- | --- |
| 领域与数据 | `packages/robot/src/domain/`、`storage/file-store.ts` | 内容验证、版本、证据、经验候选及可复制格式。独立数据目录有单写者锁并原子写入。 |
| 宿主与控制 | `host/management.ts`、`host/actions.ts`、`adapters/dsh/`、`agent.ts` | 接身份、会话与模型，执行工具权限、工作流和审批。 |
| 图形入口 | `packages/ui-robot/src/client/` | 机器人页、草稿、启动、经验审阅、产物与分享。 |
| 验证与操作 | `tests/`、`scripts/`、各包的 `tests/` | 场景测试、构建、生成远程接口、隔离运行和数据校验。 |

工作流以动作许可、步骤检查和声明的转移条件约束运行。例如审核机器人的第一步要求落地来源清单，第二步要求证据台账，最后一步要求审核报告。一个报告的存在说明产物已落地，报告中每个结论还需按证据核实。未定义情况进入等待用户状态，由用户决定怎样继续。

## 如何理解自动复盘

第一次真实审核分析了本项目数据写入失败和恢复路径，发现了临时文件清理缺口及提交结果不明确的问题。清理与状态提示已纳入当前源码。报告自身又把一条未验证推断放在事实段落里，复盘因此提出加强证据分类的建议。建议在隔离副本获准后，用一对合成正反例复跑。正例确实遗漏清理，反例覆盖相同失败路径，新版给出了预期分类。对应代码在 `examples/review-fixtures/temp-cleanup.ts`。这个结果说明该次任务的表现，普遍可靠性仍需更多任务验证。

正式分享配置对应已发布第 1 版。运行数据和个人审核记录由各自环境维护。复制型分享可以独立演进，托管邀请通过权限控制使用拥有者的部署和资料范围。

## 维护者应知道的取舍

- 宿主适配层使用公开能力。内容版本和包格式独立，宿主升级要用同一套行为重新验证。
- 外部业务动作由可信执行器登记。应用支持查看参数、审批和核对结果，当前安装不配备生产发布执行器。
- 当前交付重点是单个机器人的准备、执行、复盘与分享。多机器人自动调度、监听 PR 和跨机器部署属于后续范围。
- 包含 69 项自动化测试。使用 `node scripts/check-service-runtime.mjs` 可复现两个 Web 发布宿主上的业务集成检查。
